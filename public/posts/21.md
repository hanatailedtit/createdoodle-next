# 순차탐색 vs 이진탐색 — 언제 어떤 걸 써야 할까?

알고리즘을 공부하면서 가장 먼저 접하게 되는 개념 중 하나가 바로 탐색(Search)이다.  
탐색은 말 그대로 **원하는 데이터를 찾는 과정**을 의미하며, 거의 모든 프로그램에서 기본적으로 사용되는 중요한 개념이다.

이번 글에서는 대표적인 탐색 알고리즘인 순차탐색(Linear Search)과 이진탐색(Binary Search)을 비교하면서, 상황에 따라 어떤 알고리즘을 선택해야 하는지 정리해보려고 한다.

---

## 1. 탐색 알고리즘이란?

탐색 알고리즘은 주어진 데이터 집합에서 특정 값을 찾기 위한 방법이다.

예를 들어,

- 리스트에서 특정 숫자를 찾거나
- 배열에서 원하는 값을 찾는 상황

이 모든 것이 탐색 문제에 해당한다.

탐색은 단순해 보이지만, 데이터의 크기와 상태에 따라 **성능 차이가 매우 크게 발생**할 수 있다.

---

## 2. 순차탐색 (Linear Search)

순차탐색은 가장 기본적인 탐색 방법으로, 데이터를 처음부터 끝까지 하나씩 확인하면서 원하는 값을 찾는다.

### 동작 방식

1. 첫 번째 데이터부터 시작
2. 찾고자 하는 값과 비교
3. 같으면 종료
4. 다르면 다음 데이터로 이동
5. 끝까지 반복

### 특징

- 정렬이 필요 없다
- 구현이 매우 간단하다
- 어떤 데이터 구조에서도 사용 가능하다

### 시간복잡도

- 최악의 경우: **O(n)**
- 언제: 데이터를 끝까지 다 확인해야 하는 경우

### 예시

```c
def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1
```

### 언제 사용하면 좋을까?

- 데이터가 정렬되어 있지 않을 때
- 데이터의 양이 많지 않을 때
- 빠르게 구현해야 할 때

---

## 3. 이진탐색 (Binary Search)

이진탐색은 **정렬된 데이터**에서 사용할 수 있는 매우 효율적인 탐색 방법이다.  
중간 값을 기준으로 탐색 범위를 절반씩 줄여가며 값을 찾는다.

### 동작 방식

1. 중간값(mid)을 선택
2. 찾는 값과 비교
3. 작으면 왼쪽 탐색
4. 크면 오른쪽 탐색
5. 범위를 계속 줄이며 반복

### 특징

- 반드시 데이터가 정렬되어 있어야 한다
- 탐색 속도가 매우 빠르다
- 구현은 순차탐색보다 조금 더 복잡하다

### 시간복잡도

- 최악의 경우: **O(log n)**

### 예시

```c
def binary_search(arr, target):
    low = 0
    high = len(arr) - 1

    while low <= high:
        mid = (low + high) // 2

        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1

    return -1
```

### 언제 사용하면 좋을까?

- 데이터가 정렬되어 있을 때
- 데이터의 양이 많을 때
- 빠른 탐색이 필요할 때

---

## 4. 순차탐색 vs 이진탐색 비교

| 구분        | 순차탐색    | 이진탐색        |
| ----------- | ----------- | --------------- |
| 정렬 필요   | X           | O               |
| 속도        | 느림 (O(n)) | 빠름 (O(log n)) |
| 구현 난이도 | 쉬움        | 보통            |
| 사용 조건   | 제한 없음   | 정렬 필수       |

---

## 5. 간단한 예로 이해하기

예를 들어, 1부터 100까지 숫자가 있다고 가정해보자.

- 순차탐색:  
  1부터 하나씩 비교 -> 최악의 경우 100번 확인

- 이진탐색:  
  중간값 50부터 시작 -> 절반씩 줄임 -> 약 7번 정도면 찾음

> 데이터가 많아질수록 이 차이는 훨씬 커진다.

---

## 6. 핵심 정리

탐색 알고리즘 선택에서 가장 중요한 기준은 **데이터가 정렬되어 있는가?** 이다.

- 정렬되어 있지 않다면 -> **순차탐색**
- 정렬되어 있다면 -> **이진탐색**

이 기준만으로 대부분의 상황에서 적절한 선택을 할 수 있다.

---

## 7. 느낀 점

처음에는 단순히 "탐색 방법이 다르다" 정도로 생각했지만, 공부하면서 데이터의 상태에 따라 알고리즘 선택이 얼마나 중요한지 느끼게 되었다.

특히 이진탐색은 조건(정렬)이 맞는 경우, 성능 차이가 매우 크게 발생한다는 점이 인상적이었다.

앞으로는 단순히 알고리즘을 구현하는 것을 넘어서, "현재 상황에 어떤 알고리즘이 더 적절한가?"를 먼저 고민하는 습관을 들여야겠다고 생각이 든다.
